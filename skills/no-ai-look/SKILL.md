# 去除模板化的 AI 观感

**核心规则：每个视觉元素都说得出为什么，内容必须真实。** 只换默认样式不算修好；一种写法本身不分好坏，是否属于贯穿产品的设计语言、是否承载信息，才决定它是否模板化。

本技能定义标准和审查表。具体实现可同时加载 Waza `ui`；`frontend-design` 安装后可作为可选补充。项目有自己的视觉技能时，以项目技能为具体约束，本技能补它没覆盖的部分。用户的品牌、审美和产品偏好只写进项目或用户层，不回填通用技能。

## 1. 动手前

1. **锁定题材**：产品是什么、给谁用、页面主要任务是什么。颜色、材质和用词从行业本身找。
2. **找 2–3 个真实优秀参考**：每个只借一个可说明的决定并记录精确值（色值、字号、间距、圆角等），不整体照抄。
3. **先定设计语言**：4–6 个有名字的颜色（一个主导色、不超过两个强调色）、字体角色、字号阶梯、4/8 基数间距、分层圆角、阴影策略和图形语言。网站落成 token，App 落成颜色/字体常量。
4. **只留一处大胆元素**：其余界面安静克制。
5. **准备真实内容和状态**：真实或贴近真实的文案、数字、名字、空状态、错误状态和长文本；不用 lorem、占位产品名、无出处统计和整齐得不真实的数字。

## 2. 默认避免；确需使用时说明理由

网页：

- 靛紫到蓝渐变、渐变文字、hero 后模糊光斑。
- 居中 hero 套餐：胶囊标签、大标题、副标题、双按钮、光晕。
- 三张同构功能卡，或为了躲避它而套用的默认 Bento。
- 所有元素同一大圆角、灰色软阴影铺满、卡片套卡片、无浮层关系的毛玻璃。
- 未经选择的 Inter/Roboto/系统字体，或另一套流行默认字体。
- 每节都放全大写小标签、无顺序却编号 01/02/03、所有链接加箭头。
- 无证据的统计条、logo 墙、好评墙；全页进场动画和弹性回弹。
- “赋能、无缝、Elevate、Unleash”等空话和不具体的按钮文字。

App/桌面：

- emoji 当功能图标、与功能无关的 sparkles/zap/shield、满屏“AI 功能”标识。
- iOS 全页都是默认 insetGrouped `List/Form`、系统蓝主按钮、每页 large title、统一大阴影、金额不使用等宽数字、缺少触感反馈。
- 桌面应用像网页套壳：启动白屏、没有原生菜单和常用快捷键、Esc 不能关闭。

奶油底配赤陶、近黑底配荧光色、报纸风细线多栏也可能成为新默认；从一种模板换到另一种模板不算差异化。

## 3. 分平台

### 网站（Next.js/Vite + Tailwind）

- 清掉不使用的默认主题 token，只保留项目自己的颜色、字体和圆角。
- 使用组件库时改其源码/变量，不能只换品牌色。
- 可用 1px 间隙网格替代阴影卡片；圆角按层级分 0/4/8/12–16px；悬停优先只换背景；动效集中在一处并支持 `prefers-reduced-motion`。
- 先给用户可用的东西，再讲品牌故事。中文字体按实际字符分包，避免整套字体拖慢首屏。

### iOS（SwiftUI）

- 遵守 HIG 的可读性、动态字体、粗体文本和无障碍要求；自定义字体也不能破坏最大字号布局。
- 结构和手势遵循平台，个性放在字体角色、单一品牌色、数字排版和一处标志性交互。
- 工具类可用中性浅灰底、白表面、深色字和高信息密度，但必须结合具体题材，不照搬电商运营结构。

### Mac/Windows 桌面

- 原生优先；原生感主要来自滚动、焦点、菜单、窗口、快捷键和无障碍行为。
- Electron/Tauri 应在内容就绪后显示窗口，提供原生菜单、设置快捷键和 Esc 行为。
- Windows 11 按平台层级使用 0/4/8px 圆角，Mica 用于窗口底、Acrylic 只用于临时浮层，并选平台字体。

## 4. 字体与许可

| 字体 | 适合 | 许可注意 |
|---|---|---|
| 思源黑体/思源宋体 | 正文与标题分工 | OFL；保留许可证 |
| 霞鹜文楷 | 强调句、引文、阅读产品 | OFL 1.1；改版命名受限 |
| 得意黑 | 展示标题 | OFL；不用于正文 UI |
| MiSans/HarmonyOS Sans | 中文界面候选 | 商用前重新核对授权原文 |

外部字体、图标、截图和参考素材都要核对许可证；无法核实就不打包进产品。

## 5. 截图审查表

审查人对实际截图逐条判断：

1. 首屏能看出产品和题材；遮住 logo 后仍与同类有区别。
2. 没有无理由的紫蓝渐变、渐变文字和 hero 光斑。
3. 字体经过选择，字号层级至少三级且清晰。
4. 一个主导色、不超过两个强调色；强调色用于操作或关注点。
5. 圆角至少两个层级，阴影没有铺满所有卡片。
6. 没有三张同构功能卡、卡片套卡片和装饰性彩条。
7. 没有 emoji 或无关通用图标冒充功能图形。
8. 数字、评价、logo、人名有真实依据。
9. 按钮描述具体动作，文案没有空话。
10. 标签、编号、元信息和箭头都承载信息。
11. 只有一个记忆点，其余元素克制。
12. 对比度、手机宽度、长文本、空/错状态可用。
13. 原生 App 的菜单、快捷键、窗口、系统控件和无障碍符合平台。
14. 同题材换一个 agent 仍会做得一样时，至少重做一项字体、颜色或版式决定。

任一项不过且会影响实际观感或使用，就是必须修改的问题。研究依据见 `references/research-2026-10-11.md`。
