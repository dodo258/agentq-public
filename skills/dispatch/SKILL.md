# 派活

收到当前 BACKLOG 待办明确执行合同的进程（通常带 `AGENTQ_JOB`）应使用 `agent-task` 亲自完成，不用本技能重新派发同一任务。

本技能只负责把需求写清并启动调度，不在当前会话等待开发完成。用户/项目层保存项目别名、权限和通知偏好；通用技能不写死个人项目、账号或渠道。

## 1. 识别项目

- 会话已位于 Git 项目目录时，使用该项目。
- 否则在 `${AGENTQ_PROJECTS_ROOT:-$HOME/projects}` 下按目录名和各项目 `AGENTS.md` 的项目说明匹配。
- 无法唯一匹配时，只列候选并问一次；不要凭个人别名猜测。
- 项目不存在且需求是新建项目时，加载 `new-project`。

## 2. 写入 BACKLOG

1. 打开项目 `docs/BACKLOG.md`；不存在时从 `${AGENTQ_SHARE_DIR:-$HOME/.local/share/agentq}/templates/BACKLOG.md` 生成，已有等价任务文件则沿用，不并建一套。
2. 一项需求一条，写入「待做」：

   ```text
   - [ ] 标题 —— 要什么；验收：可观察结果和验证方式；范围：已知页面/文件；理解成：……；不是：……
   ```

3. 条目保存产品目标、验收和授权范围；本次入口会话不直接实现、不等待后台等派活步骤不写成后台任务的禁止实现指令。
4. 用户一句话包含多个可独立验收目标时拆开；有顺序或前置条件时写清。
5. 验收后的意见写成 `验收 <原条目标题> 的意见`；修复近期已合并改动时记录对应提交号，供质量统计使用。
6. 用户回复「等用户决定」的条目时，把决定和原分支写回该条目，再移到「待做」顶部。
7. 只提交本次改动的 BACKLOG；不带入其他会话文件。

## 3. 交给 agentq

- 用户说“夜里做”或“只加到待办”：写入后停止，留给定时调度。
- 其他派活请求：对每条执行 `agentq run <项目目录名> <标题关键词>`，只需等命令返回启动结果，不等开发任务完成。
- 并发已满或额度冷却时，保留 BACKLOG 条目，由后续调度接手；不要绕过限制。自动调度暂停不会阻止显式的 `agentq run`；用户仅要加入待办时不调用 run。
- 进度通过 `agentq status` 和 `agentq logs <任务ID>` 查询；报告目录按本机 agentq 配置读取，不在技能里写死通知渠道。

## 4. 回答

每条一行说明：是否已启动、任务 ID（如有）、完成后按哪条验收、如何查询进度。不要宣称尚未完成的结果，也不要因为派活而扩大远程推送、发布或付费授权。
