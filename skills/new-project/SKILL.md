# 新建项目

默认补全可逆细节并记录假设；只有不可逆数据、账号、付款、公开发布或方向完全不同的关键选择才需要先确认。用户或组织自己的技术偏好、仓库命名和长期授权留在用户层。

## 1. 创建目录

- 根目录为 `${AGENTQ_PROJECTS_ROOT:-$HOME/projects}`，项目目录名用简短、小写、连字符英文名；目标已存在就停止并说明。
- `git init -b main`，按技术栈生成 `.gitignore`，加入 `.claude/worktrees/`。
- 优先沿用用户/组织说明中的技术栈；没有指定时按项目平台和生态选成熟、可维护的方案，并把假设写进方案。

## 2. 建立项目记录

从 `${AGENTQ_SHARE_DIR:-$HOME/.local/share/agentq}/templates/` 生成：

- `AGENTS.md`
- `PROGRESS.md`
- `DECISIONS.md`
- `LESSONS.md`
- `docs/BACKLOG.md`

已有等价文件时沿用，不覆盖。`CLAUDE.md` 可用一行 `@AGENTS.md` 作为 Claude 入口；项目稳定信息写在 `AGENTS.md`，用户私有规则留在用户层。

## 3. 远程仓库与 CI

本地项目初始化是开发任务的一部分；创建远程仓库、push、设置可见性、配置仓库设置或发布，必须由当前任务或用户/项目规则明确授权。

获得授权后：

- 使用用户层配置的账号/组织和仓库命名，不在通用技能里写死 owner。
- 可见性、许可证和分支策略按任务要求；没有明确公开授权时不得创建公开仓库。
- 给需要协作的项目配最小 CI，在 push/PR 上运行项目检查。
- 删除仓库、修改仓库设置、正式 release 仍需覆盖对应动作的明确授权。

## 4. 有界面的项目

加载 `no-ai-look` 和项目视觉技能，确定题材、真实参考、颜色/字体/间距/圆角和标志性元素，并把稳定设计语言写进项目方案或规则。用户提供的品牌与视觉偏好只保存在项目或用户层。

## 5. 首批任务

先加载 `prior-art` 研究同类和差异化，再将需求拆成可独立验收的 BACKLOG 条目。大需求加载 `think` 写方案；随后用 `dispatch` 派出当前授权范围内的开发任务。

## 6. 交接

说明项目路径、已完成的初始化、首批待办、关键假设和未执行的远程动作。不能把“本地已建好”说成“已发布”或“已备份”。
